# 墨稿 · 浏览器发布助手（预览版 0.2.0）

在 Obsidian 墨稿里选择平台，点击 **发布到公众号 / 发布到小红书 / 发布到知乎**。扩展自动接收当前排版稿，打开对应平台的新稿入口；如果需要登录，由用户在平台页面登录，完成后自动继续同步正文、上传图片并单独填写标题。最后的 **发表** 由用户确认。

日常发布不需要导出、选文件、读取稿件、配对或再点击导入。发布的是点击时墨稿里的最新排版稿，包含尚未保存的修改；图片按正文中的位置传递。

## 安装一次

需要配套 Obsidian 墨稿 **0.1.5 预览构建**和 Chrome / Edge。0.1.4 没有发布按钮。扩展尚未上架商店，不能自动安装浏览器扩展。

- 第一次在墨稿点发布，未检测到扩展会自动进入安装引导页。点击 **下载墨稿浏览器扩展**，解压，打开浏览器的扩展管理页，启用开发者模式，选择 **加载已解压的扩展程序**。安装完成回到引导页点 **继续发布**。
- 已加载旧版扩展的开发用户，在原目录更新构建文件后，需在扩展管理页重新加载，并接受新增的三个平台与本机地址权限。
- 安装引导下载的是当前 Obsidian 构建附带的扩展 ZIP，直接由本机提供，无需登录 GitHub或定位 Vault 文件。
- 用支持此扩展的浏览器打开发布链接；若默认浏览器是 Safari，可将发布链接打开在 Chrome / Edge。

## 发布过程

浏览器会显示一个进度页，同时打开目标平台。保持两个页面打开；登录、验证码由用户完成。登录后会等待新稿编辑器并自动同步。小红书会点击 **新的创作**；公众号会寻找当前页面上可见的新建图文链接，知乎打开专栏写作入口。平台页面变化而无法找到新稿入口时，进度会停在等待状态，不会声称同步成功。

正文先通过编辑器的粘贴处理器进入，再依次将实际图片文件交给平台编辑器上传。每张图片必须变成可显示的平台图片地址，才继续下一张；最后检查数量、图片前后文字与标题。不覆盖已有草稿，不自动保存/发表，不接触账号密码或 Cookie。

出现上传拒绝、重复图片、超时、位置变化或用户操作正文时会停止，保留已经同步的部分。再次点击墨稿发布会新开平台页；不会在部分完成的稿件上叠加全文。平台恢复了已有草稿时也会停止以免覆盖。平台媒体库里已经上传的图片不会被删除。

## 验证边界

自动化覆盖发布快照、本机传递、等待登录后继续、正文与图片依次传递、已有草稿保护、取消和上传失败。编辑器测试使用真实 Tiptap / ProseMirror 和模拟上传处理器。

**完整扩展在真实平台的验收仍未完成。** 2026-09-08 的小红书原生粘贴测试确认图片能上传到 xhscdn.com，并在暂存、退出、重开浏览器本地草稿后保留两图与文字顺序；但每次原生粘贴出现两份图片，手动删除重复项后才通过检查，这不等于扩展验收通过。公众号、知乎的真实兼容性也仍待验证。

## 数据与权限

- `scripting` 及本机、公众号、小红书创作平台、知乎专栏的限定地址权限，用于从 Obsidian 发起后自动打开和操作新建的目标标签页。没有 Cookie、剪贴板、调试器、全站访问或持久化稿件权限。
- Obsidian 仅在 `127.0.0.1` 提供本次点击的稿件快照。随机端口避免多个 Vault 冲突；随机任务地址有效期 30 分钟。任务被一个发布窗口接收后，其他窗口不能重复执行；完成或停止后删除。没有读取当前笔记、枚举 Vault 或任意文件的浏览器接口。
- 本机常驻启动脚本只识别 `/publish/` 下的随机任务链接。平台脚本只在本次任务的新标签页注入。用户未点击发布时不会自动同步内容。
- 图片由所选平台自身的编辑器上传，不经第三方中转服务，不调用未公开的登录/上传接口。
- 每张图片最多 8 MB，每篇最多 40 个图片位置，总稿件最多 64 MB。平台格式与大小上限可能更严格。平台可能重设模板样式，不保证像素一致。
- 完成消息仅确认编辑器收到可显示的图文。请检查平台保存状态并重新打开草稿核验；小红书当前长文草稿提示保存在本浏览器，不代表服务端持久化。

## 开发

仓库根目录运行 `npm run verify:extension`。输出 `dist/mogao-browser-extension/` 和 `dist/mogao-browser-extension-0.2.0-preview.zip`。`npm run build` 将扩展 ZIP 内置进 Obsidian 的 `main.js`，仍只需标准的三个插件文件。插件商城 Release 不附加独立扩展文件。

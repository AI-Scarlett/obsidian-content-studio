# 墨稿 · 浏览器发布助手（预览版 0.3.8）

点击浏览器工具栏的 **墨稿图标**，会请求唤醒 Obsidian 并打开墨稿工作台。已打开的工作台保留未保存稿件；首次打开时读取当前笔记。首次调用可能需要确认“打开 Obsidian”。未启动 Obsidian 时会由系统启动，上次使用的仓库需启用墨稿。如果浏览器没有打开应用，可在新开的“回到墨稿”页点击重试。当前页若是待接收稿件的连接页，图标仍会继续该次同步。

配套 Obsidian 墨稿 **0.1.14**。在墨稿里选择公众号、知乎、小红书或 X，点击 **发布到平台**。当前标题、排版正文和图片文件会一起传给浏览器助手；没有每篇稿件的导入、导出或选文件步骤。平台未登录时，由你登录后继续。最终发表仍由你操作。

## 本版的同步方式

| 平台 | 实现 |
| --- | --- |
| 公众号 | 参考 MultiPost，在当前登录会话中上传图片素材，替换正文图片地址，创建一篇草稿，再根据返回的草稿 ID 打开编辑页。保留正文 HTML 样式。没有选择封面时，草稿封面留空，发表前需在平台确认。 |
| 知乎 | 接入 Draft.js 文档状态，按标题、段落、列表、强调与链接写入；通过原生图片工具栏自动提交图片文件，再把上传生成的媒体文档块放回原位置。认可实际草稿使用的 `pic-private.zhihu.com` 图片域名。 |
| 小红书长文 | 接入 Tiptap 文档状态。PNG / JPEG 调用编辑器原生图片处理回调，先上传，再插入平台图片，避免工具栏预览与上传回调的竞态；其他类型保留原生工具栏路径。扩展直接提供图片字节，不读取系统剪贴板，用户无需找文件。随后把完整图片文档块放回原位置。 |
| X 长文 | 墨稿新增 **发布到 X 长文**。参考 xPoster 的 Draft.js 处理方式，写入结构化正文，调用 X 的真实媒体上传处理函数；媒体 ID 和可显示图片都就绪后才安放图片。需要账号具有 X Articles 编辑权限。 |

知乎、小红书和 X 使用各平台支持的语义格式；自定义字体、颜色和模板装饰不保证原样保留。X 与小红书现可在墨稿底部直接点击“发布长文”或“发布图文”，不需要先选择发布类型。X 串文仍使用单独的复制入口。普通图文以纯文本及图片附件呈现，不支持长文模板装饰。

## 普通图文

选择小红书“普通图文”时，助手打开上传图文页。先逐张上传笔记中的图片，随后在出现的编辑区填写标题、正文，通过实际话题候选插入原生标签。只选择名称完全一致的候选，不伪造话题 ID；未找到或达到账号限制时停止并显示原因。

选择 X“普通图文”时，助手打开 `/compose/post` 弹窗，通过原生 Draft.js 模型填写标题首行、正文和话题，再逐张添加图片附件。只操作本次弹窗，不触碰背景首页编辑器。图文帖附件位置由 X 决定，不能放在正文段落之间。

小红书支持 1–18 张图、20 字标题、正文含话题 1,000 字，最多 10 个话题（平台对部分账号可能限制更少）；X 支持最多 4 张图。墨稿会完整发送 X 文案，由 X 根据账号类型和当前平台规则判断字数与是否允许发表，不在本地拦截、截断或拆帖。支持 PNG/JPEG/WebP；X 每张上限 5 MB，小红书本工具上限 8 MB。不会静默丢弃多余图片。

小红书以原生图片组件的 fileId 和非处理状态核对上传；X 核对本次弹窗的图片附件顺序、解码状态及提交控件可用状态。X 的本地预览和提交控件状态不构成服务器保存证明。最终发布控件始终不被点击。

## 安装与升级

扩展尚未上架 Chrome 扩展商店。推荐在墨稿中点击发布：如果没有检测到助手，安装引导会提供与当前插件版本匹配的下载。也可以直接从 GitHub Actions 获取：

1. 打开仓库的 [Actions](https://github.com/AI-Scarlett/obsidian-content-studio/actions) 页面，进入最新成功的 **Verify plugin** 或 **Release plugin** 运行。
2. 在页面底部 **Artifacts** 下载 `content-studio-package` 或 `content-studio-0.1.17-package`，解压后找到 `mogao-browser-extension-0.3.8-preview.zip`。
3. 解压浏览器助手 ZIP。在 Chrome 地址栏打开 `chrome://extensions`（Edge 使用 `edge://extensions`），打开 **开发者模式**。
4. 点击 **加载已解压的扩展程序**，选择解压后的 `mogao-browser-extension` 文件夹；不要选择 ZIP 文件本身。
5. 在扩展卡片确认版本是 **0.3.8**。首次点击工具栏图标时，浏览器可能询问是否打开 Obsidian，请允许。

已经加载过扩展：将新版文件更新到原来的扩展目录，然后在扩展管理页点击墨稿卡片的 **重新加载**，确认显示 **0.3.8**。从 0.3.0 更新到本版没有新增网站权限。仅刷新公众号页面不会更新扩展。

Obsidian 0.1.14 会拒绝旧版助手领取稿件，并明确提示重新加载，避免磁盘文件已经更新而浏览器仍使用旧的图片粘贴逻辑。重新加载后，回墨稿再点发布即可；无须导出笔记。

## 失败与草稿保护

- 长文标题在正文同步开始时单独填写；小红书普通图文需先上传图片才能显示标题和正文编辑区。
- 已有内容的编辑器不会被覆盖。公众号始终创建新草稿，不修改原有草稿。
- 上传产生多余图片、超时、位置不唯一、平台文档不兼容或用户开始操作正文时会停止，已写内容和素材保留。
- 公众号创建草稿的响应不确定时，不自动重试。请先检查草稿箱，避免重复创建。
- 同步完成会核对标题、图片数量、图片地址与相邻正文。应再检查平台保存状态，并重新打开草稿确认；这不等于自动发表。

## 数据与权限

只申请 `scripting` 和本机回环地址、公众号、小红书创作平台、知乎专栏、X 的限定网站权限。没有 Cookie、系统剪贴板、调试器或全站访问权限。

平台代码仅在墨稿主动发送稿件后，注入本次打开的目标标签页。为了调用编辑器的实际文档和上传功能，本版使用 Chrome 的 MAIN world；不接受网页 `postMessage` 指令，不加载远程脚本，不导出平台会话。

公众号使用网页当前登录会话及其素材/草稿接口；不要求在 Obsidian 填 AppID/AppSecret，也不把登录参数传回 Obsidian 或写入日志。其他平台的图片由平台原生上传处理器处理，没有第三方中转。

Obsidian 仅在 `127.0.0.1` 提供这次点击的冻结稿件。随机任务地址有效期 30 分钟，只能由一个发布窗口领取；没有浏览器任意读取 Vault 的接口。图片每张最多 8 MB，每篇最多 40 个图片位置，总稿件最多 64 MB。

## 检查与限制

本地检查覆盖真实 Tiptap / Draft.js 文档模型、原生上传控件的测试替身、三张图片顺序、重复图片地址、标题分离、上传失败、公众号草稿接口契约、取消、重复任务和旧扩展拒绝。

这些检查不会调用真实账号上传接口，不等于四个平台已经完成端到端验收。实际网页版本、账号权限、平台素材处理和草稿重开效果仍需平台验证。不会把测试替身产生的图片当作真实上传证据。

## 构建与开源来源

仓库根目录运行 `npm run verify:extension`。输出 `dist/mogao-browser-extension/` 和 `dist/mogao-browser-extension-0.3.8-preview.zip`。`npm run build` 把扩展 ZIP 内置到 Obsidian 的 `main.js`。

Draft.js 部分改编自 xPoster（MIT）；公众号素材/草稿协议部分改编自 MultiPost-Extension（Apache-2.0）。来源、固定提交、修改说明和许可证保存在源码、`THIRD_PARTY_NOTICES.md` 及 `licenses/` 中。未复制 Wechatsync 的 GPL 源码或无许可证的 rednote-skills 代码。

0.3.3 新增图标唤醒墨稿入口，不增加扩展权限。以下图片修复来自 0.3.2，仍需真实平台验收：0.3.2 移除了知乎和 X 的 DOM 种子文字初始化，修正 Draft.js 空实体值导致的保存错误，并调整小红书 PNG / JPEG 上传入口。旧助手会被阻止领取新任务；发布进度页顶部显示实际运行版本。0.3.1 的图片数组识别修复单独不足以解决小红书临时预览停滞，真实多图上传仍须验收。

# 墨稿 · 整篇图文导入（预览版）

把墨稿文章中的正文和图片按原位置导入长文编辑器，不需要逐张手动复制。它是配套的 Chrome / Edge 扩展，不是 Obsidian 社区插件更新。

**当前状态：已实现导入流程，尚未完成三个平台真实上传及草稿保存验证。请先用无敏感内容的空白测试草稿。小红书长文编辑器的 Tiptap 结构已经只读确认；公众号与知乎适配为待实测。不能把本地回归测试视为平台已支持。**

## 安装

1. 将 `mogao-browser-extension-0.1.0-preview.zip` 解压到固定目录。
2. Chrome 打开 `chrome://extensions`（Edge 为 `edge://extensions`），开启“开发者模式”。
3. 选择“加载已解压的扩展程序”，选取包含 `manifest.json` 的目录。
4. 在浏览器工具栏固定“墨稿 · 整篇图文导入”。

包内的 **sample-article.html** 是两张合成图片的测试稿，可先直接选择这个文件。绿色图有一个方块，红色图有两个方块；图注应留在各自原位置。

## 一次导入整篇文章

1. 墨稿中选择公众号、小红书或知乎排版，等待所有图片载入，点“浏览器导入包”。保存 `article-mogao.json`。
   - 现有 **0.1.4** 不用升级也能测试：点“完整内容包”，选用其中的 **article.html**。不要选择模板 JSON 或导出清单。
2. 在对应平台新建**标题与正文都为空**的长文草稿。小红书必须是长文编辑页，知乎为专栏文章。
3. 在这个网页上点击扩展图标。扩展会打开独立导入窗口，上传期间不会因焦点切换关闭。
4. 检查平台识别结果，选择整篇内容包，点“导入整篇图文”。
5. 扩展先通过编辑器的粘贴入口写入整篇正文，再自动逐个把图片文件交给上传处理器；等待图片变成可显示的平台图片地址，再继续下一张。用户不需要逐张复制。
6. 最后核对图片数量、顺序，以及每张图片前后的正文；标题写入标题栏。确认平台自动保存完成后，再手动预览与发表。

导入期间保持目标编辑页打开，不要操作正文。如果平台拒绝文件粘贴、出现验证或上传超时，扩展会停止并保留已导入部分。不要在部分导入的文章上直接重试；使用新草稿，或先自行清空。上传失败后可能留下 `MOGAOIMAGE…END` 位置标记，检查时应删除。扩展不删除平台媒体库里已上传的图片。

## 实现与限制

- `activeTab` + `scripting`：只在点击扩展时接触当前标签页；没有全站常驻脚本、Cookie、剪贴板或调试器权限。
- 通过编辑器自身的 HTML / File 粘贴处理器触发上传。不读取平台登录凭据，不直接调用未公开的上传 API，也不修改编辑器 innerHTML 冒充导入。
- 本地图片路径不能让网页读取磁盘，内容包因此包含真实图片字节。导入到哪个平台，就由那个平台接收选定的正文与图片。没有第三方上传中转服务器。
- PNG/JPEG/GIF/WebP/AVIF，每张最多 8 MB，每篇最多 40 个图片位置，内容包最多 64 MB。具体格式、大小、图数限制以平台为准。重复图片仍在每个原位置上传。
- 平台可以重设字体、间距、颜色和复杂装饰。本工具检查内容与图片位置，不保证模板像素一致。
- 若平台只保留 blob URL、图片被其内部模型重排、粘贴事件被拒绝，当前适配会停止，不能假称图片已上传。
- 结束消息只确认编辑器中可见的图文，不证明服务器已保存。必须在平台自动保存后自行重新打开草稿核验。
- 用户操作、关闭页面或点“停止导入”会终止后续步骤；已经发给平台的上传请求可能继续完成。
- 公众号也可走官方 `media/uploadimg` + `draft/add` 路线，需要账号权限及接口配置；这条接口路线不包含在本扩展中。

## 开发

在仓库根目录执行 `npm run verify:extension`。产物在 `dist/mogao-browser-extension/`，分发 ZIP 在 `dist/`。不要把扩展文件附到 Obsidian 插件的三个标准 Release 附件里。

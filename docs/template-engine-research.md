## 旧实现的问题

- 六套内置模板共用 16px、1.85 行高以及相同段距。虽然配色、标题处理和字体族有变化，正文阅读节奏几乎没有差异。原生 Obsidian 检查确认旧版并非完全不应用样式。
- 采样器手工处理 CSS 选择器和优先级，忽略了 CSS 变量、部分结构选择器与简写声明。
- 外框、色块、编号、文字被合并到单层角色样式，丢失它们之间的关系。例如内层文字底色可能被放大为整行色块。
- 居中、加粗的小字号图片说明可能因重复次数多，被错选为主要标题。
- 正文部分字体属性只放在最外层容器，不能可靠抵御宿主主题或粘贴目标的段落默认样式。

## 0.1.18 的处理

1. 用 Juice 的 client API 解析 CSS 层叠、变量与可解析的伪元素。只处理已取得的文本，不使用资源下载 API；构建时将 Cheerio 限定为 slim 解析器。
2. 为可识别的二、三级标题保存有大小和深度上限的结构树，分别记录外框、色块、文字插槽与编号插槽。模板不保存原文章文字、HTML、图片地址或脚本；导入时再次验证。
3. 排除小于正文字号的说明文字，优先采样比正文大的标题。不能识别的结构继续使用语义样式，并保留复刻边界说明。
4. 六套内置模板拥有各自的字号、行距、段距、缩进和字距。复制、浏览器投递与预览共用渲染结果，并将继承的文字样式写到元素本身。
5. 已有模板保留不动；重新读取参考链接后另存，才能获得新采样结果。

## 验证边界

回归覆盖 CSS 变量、结构选择器、标题双层盒子、编号顺序、原文不入模板、输入清洗、模板选择到复制的完整路径，以及宿主段落样式干扰。真实 Chromium 的对照页面确认：正文 17px、行高 30.6px、字距 1px、段距 26px；标题文字 22px 白色，外框、编号与内层色块分离。

这些结果证明上述通用机制，不代表任意公众号文章都可以逐像素复刻。图片中的装饰文字、整篇多栏设计、动画和无法取得的字体仍不支持。当前用户保存的参考链接在本次读取时返回微信验证页，未取得原文，因而不能声称已验证该链接的视觉还原度。平台最后粘贴／发布效果也不能由本地测试代替。

# Mogao Content Studio 0.1.7 — platform adapter preview

The previous companion used one synthetic file-paste path for different editors. Real failed drafts showed a rejected Zhihu private image host, damaged Xiaohongshu markers and missing X integration. This preview replaces that path with platform adapters and bundles browser assistant **0.3.0**.

- WeChat uploads actual media in the current browser session, writes one styled draft and opens the editor using the returned draft ID. Uncertain draft creation is never retried automatically. Covers remain for the user to confirm in the platform.
- Xiaohongshu long-form uses the native toolbar upload and Tiptap document transactions to place the resulting image nodes.
- Zhihu uses Draft.js document state and the native image toolbar, including the observed private image CDN.
- X Articles gains a publish button, structured document writing and native media uploading based on xPoster. A completed media identity and decoded platform image are required before an image is accepted. Articles account access is required.
- Titles are filled separately at the start. Old companion versions cannot claim a new delivery, preventing stale runtimes from silently using the old adapter.

Install only `main.js`, `styles.css`, and `manifest.json` into the Obsidian plugin folder, preserving `data.json`. Update the existing unpacked browser extension directory and reload the extension once; X requires its new site permission. Per-article file selection is not part of the workflow.

Source adaptations preserve xPoster MIT and MultiPost Apache-2.0 attribution. No GPL code from Wechatsync or unlicensed rednote-skills source is included.

Validation includes TypeScript, plugin lint/CSS lint, article handoff tests, real Tiptap and Draft.js models with upload substitutes, and offline WeChat request/response contracts. These checks are not live platform acceptance. Browser reload and WeChat editor automation were blocked by the tool URL policy in this session; source deployment must be distinguished from browser runtime activation. Final publication is never automated. This remains a preview and does not replace the marketplace release until platform acceptance.

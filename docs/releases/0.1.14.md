# Mogao Content Studio 0.1.14 / browser assistant 0.3.7 preview

X and Xiaohongshu now have two direct publishing actions: **发布长文** and **发布图文**. The mode dropdown is removed. Each button sends its own explicit mode; switching back to articles after a photo post cannot accidentally send another photo post. Topics remain editable above the actions.

X text is sent intact without a local 280-character gate. The extension also stops treating a disabled native Post button as a failed transfer. X handles account-specific length and publishing eligibility. Existing image constraints remain; no truncation, splitting or final publication is added.

Xiaohongshu photo-post upload completion no longer depends on the Vue devtools DOM property `__vueParentComponent.props.img.fileId`. That property is not a supported production interface and its absence made the old code time out after receiving the first image, before it ever wrote the title/body. The adapter now checks the native upload/error/processing masks, decoded previews and the native Edit control, then uses preview URLs to verify image order. These signals show native UI readiness, not proof of a server-saved draft.

The first photo reveals the form. The title and body are written immediately once both fields appear, before waiting for the photo completion check; native topic selection follows after all photos are received. Existing draft text or user edits still stop synchronization and remain untouched.

Protocol 9 and MAIN runtime V9 require browser assistant 0.3.7. Updating files alone does not reload an unpacked extension. Permissions are unchanged.

## Validation boundaries

Local plugin lint, CSS lint, TypeScript, 100 plugin tests, 75 companion tests, both builds and packaging passed.

Regression coverage uses the production-shaped Xiaohongshu DOM without Vue devtools properties, confirms title/body after the first image including a pending upload, checks subsequent user edits, and preserves incomplete/failed-image detection. X coverage sends long captions with a disabled native Post button and verifies the full caption and photos remain present. Studio coverage exercises both buttons alternately and confirms long X text reaches the bridge intact.

Live read-only inspection on 2026-09-09 found the user's image present in the Xiaohongshu form, with empty native title/body fields. The DOM includes `.hover-mask .edit-btn` after upload, matching the platform's public SingleImg component. No existing draft was overwritten or published. Complete real-account acceptance of this revision remains pending because the automation's file-upload access is blocked.

# Mogao Content Studio 0.1.11 / browser assistant 0.3.4 preview

Fixes three adapter issues identified from the user's live Zhihu and X drafts:

- Zhihu's image toolbar opens the material-library dialog rather than immediately invoking a file picker. The adapter now supplies one image to the body editor's dedicated multiple-image input, excluding document import and cover inputs. If that input is absent, it recognizes the newly opened local-image dialog and continues through its image input.
- X retains blob previews after upload. Reopening the saved draft in a fresh browser tab showed the same image with a new blob URL. Requiring a CDN URL kept the first upload at the end and prevented subsequent images. X validation now binds each decoded image to its exact native atomic block and assigned MEDIA ID, including IDs in media-item arrays. DOM remounts and blob-to-CDN transitions retain this identity. Unconfirmed blobs remain rejected; each uploaded block moves to its original marker before continuing.
- X preparation recognizes Write / 写文章, checks text, title and aria-label independently, ignores disabled controls and existing draft links, and still clicks creation at most once. A manual UI check of the native create control opened a blank editor; that test draft was removed.

The bridge and MAIN adapter advance to protocol 6 so an older assistant cannot reuse the previous logic. Update both components and reload the existing unpacked extension. No permissions are added and final publication remains manual.

Validation: 98 plugin tests and 54 companion tests pass, plus lint, CSS lint, TypeScript checks, builds and the compiled-plugin package check. New regressions cover three uploads through both Zhihu routes, X blob previews with delayed media IDs and remounted DOM, original placement, unconfirmed uploads and localized creation. These use editor-model libraries with simulated uploaders. Live observations establish the failures and the persisted first X image, not successful three-image delivery by this build. Full live upload, autosave and reopen acceptance remains pending browser reload and the automation upload permission.
